# TurboKey

[English](../README.md) · [简体中文](README.zh.md) · [繁體中文](README.zh-Hant.md) · [日本語](README.ja.md) · [한국어](README.ko.md) · [Español](README.es.md) · [Français](README.fr.md) · [Deutsch](README.de.md) · **Русский** · [Português](README.pt.md) · [Italiano](README.it.md) · [العربية](README.ar.md) · [עברית](README.he.md)

Лёгкий инструмент автонажатия клавиш (rapid-fire / turbo) для Windows с нативным GUI. Привяжите клавишу к автоповтору самой себя — или другой клавиши — либо пока она удерживается, либо как переключатель вкл/выкл. У каждого правила свой интервал.

Работает с обычными приложениями и с играми: клавиши вводятся как аппаратные **скан-коды** через `SendInput` (поэтому их принимают игры на DirectInput), и каждое нажатие кратко удерживается, чтобы игры с опросом надёжно его считывали.

> Только Windows. Сделано на Go + [lxn/walk](https://github.com/lxn/walk) (нативные элементы Win32), единый автономный исполняемый файл, без установки среды выполнения.

## Загрузка

Возьмите последний `turbokey.exe` на странице [Releases](../../releases). Каждый push в `main` автоматически собирает и публикует новый версионированный релиз через GitHub Actions.

## Возможности

- Для каждого правила: **клавиша-триггер**, **клавиша вывода** (по умолчанию — триггер), **режим**, **интервал** и включение/выключение.
- Клавиши клавиатуры **или кнопки мыши** (левая / правая / средняя / X1 / X2) в качестве триггера и вывода.
- Два режима на правило:
  - **Удержание** — повторяет, пока клавиша-триггер физически удерживается.
  - **Переключение** — одно нажатие запускает повтор, следующее останавливает.
- Глобальный главный переключатель с горячей клавишей **F8**.
- При желании можно ограничить автонажатие конкретными приложениями (по имени процесса); пусто = работает везде.
- **Системный трей**: закрытие окна сворачивает его в трей (инструмент продолжает работать). Левый клик по значку восстанавливает окно; правый клик открывает меню для показа окна, переключения главного выключателя или выхода.
- Необязательный **Запуск с Windows**, зарегистрированный как запланированная задача, чтобы запускаться с повышенными правами при входе без запроса UAC.
- Правила сохраняются в `config.json` рядом с исполняемым файлом и перечитываются при запуске.
- Локализованный интерфейс на 13 языках (включая арабский и иврит справа налево с полностью зеркальной раскладкой), автоопределение из ОС, с выбором в приложении.
- Инструмент отфильтровывает свой собственный синтетический ввод, поэтому никогда не срабатывает повторно сам на себя.

## Как это работает

- Низкоуровневый хук клавиатуры `WH_KEYBOARD_LL` обнаруживает ваши нажатия и проглатывает настроенную клавишу-триггер, так что игра видит только чистые повторяющиеся импульсы.
- Каждый импульс — это `клавиша вниз → удержание ~30мс → клавиша вверх`, отправляемый с `KEYEVENTF_SCANCODE`. Удержание необходимо: игра с опросом считывает состояние клавиш каждый кадр и пропустила бы пару вниз/вверх, попавшую между двумя выборками.
- Синтетические события помечаются через `dwExtraInfo`, поэтому хук распознаёт свои собственные введённые клавиши и пропускает их, а не реагирует на них.

## Требования

- Windows 10/11 (x64).
- **Права администратора.** Исполняемый файл запрашивает повышение автоматически (запрос UAC при запуске). Это нужно, потому что Windows UIPI блокирует доступ введённого ввода от непривилегированного процесса к привилегированным окнам — а многие игры работают с повышенными правами.

## Сборка

CGO не требуется, поэтому возможна кросс-компиляция в Windows из Linux/WSL или нативная сборка в Windows.

```sh
# Linux / WSL (кросс-компиляция) или Windows (Git Bash):
./build.sh
# -> turbokey.exe
```

Скрипт устанавливает `rsrc`, чтобы встроить манифест приложения (Common Controls v6, поддержка DPI, requireAdministrator), затем запускает `go build`. Сборка вручную:

```sh
go install github.com/akavel/rsrc@latest
rsrc -manifest cmd/turbokey/app.manifest -ico cmd/turbokey/icon.ico -arch amd64 -o cmd/turbokey/rsrc_windows_amd64.syso
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 \
  go build -trimpath -ldflags "-H windowsgui -s -w" -o turbokey.exe ./cmd/turbokey
```

## Структура проекта

```
cmd/turbokey/      точка входа (main) + манифест приложения Windows + значок
cmd/gen-icon/      генератор значков при сборке (рендерит icon.ico / icon.png)
internal/keys/     таблица клавиш и кнопок мыши; сопоставление имя <-> виртуальный код клавиши
internal/i18n/     локализация UI; встроенные JSON-каталоги сообщений (locales/)
internal/config/   модель правил и загрузка/сохранение config.json
internal/winput/   обёртки Win32: хуки клавиатуры и мыши, SendInput, передний план
internal/engine/   движок автонажатия: диспетчеризация хуков, главный переключатель, воркеры
internal/ui/       нативный GUI Win32 (lxn/walk)
internal/autostart/ запланированная задача при входе (Запуск с Windows)
internal/buildinfo/ версия сборки, внедряется через -ldflags
```

## Использование

1. Запустите `turbokey.exe` и примите запрос UAC.
2. В редакторе выберите **клавишу-триггер**, **клавишу вывода** (по умолчанию = как триггер), **режим** и **интервал (мс)**, затем нажмите **Добавить**.
3. Чтобы изменить правило, щёлкните по нему (его значения загрузятся в редактор), отредактируйте и нажмите **Обновить**. Двойной щелчок по строке включает/выключает её; **Удалить** убирает её.
4. Нажмите **F8** (или поставьте галочку главного переключателя) для активации, затем нажмите клавишу-триггер для срабатывания. Нажмите **F8** снова, когда закончите.

Примечания:
- Интервал — это промежуток *между* нажатиями; каждое нажатие также удерживает клавишу ~30мс, поэтому практический потолок — около 25-30 нажатий в секунду. Этого с избытком хватит для любого игрового навыка — нажимать быстрее бесполезно, потому что игра считывает покадрово.
- Пока главный переключатель включён, настроенные клавиши-триггеры перехватываются во **всех** приложениях, не только в играх. Выключайте его (F8), когда не используете.
- F8 зарезервирована как главная горячая клавиша, пока инструмент работает.

## Конфигурация

`config.json` (создаётся рядом с исполняемым файлом) удобочитаем:

```json
{
  "rules": [
    { "name": "attack", "trigger": "J", "output": "", "mode": "hold",   "interval": 10, "enabled": true },
    { "name": "skill",  "trigger": "K", "output": "", "mode": "toggle", "interval": 50, "enabled": false }
  ]
}
```

- `output: ""` означает «как клавиша-триггер».
- `mode`: `"hold"` или `"toggle"`.
- Имена клавиш: `A`–`Z`, `0`–`9`, `F1`–`F12`, `Space`, `Enter`, `Esc`, `Tab`, `↑ ↓ ← →`, `Ctrl`, `Alt`, `Shift`, а также кнопки мыши `Mouse Left`, `Mouse Right`, `Mouse Mid`, `Mouse X1`, `Mouse X2`. (Это нейтральные к языку идентификаторы, они не переводятся, поэтому конфигурация остаётся валидной при смене языка UI.)

## Ограничение конкретными приложениями

По умолчанию автонажатие активно в каждом приложении. Чтобы ограничить его, заполните поле «Активные приложения» одним или несколькими именами процессов (например, `DNFGame.exe`, через запятую). Тогда автонажатие включается только пока одно из этих приложений на переднем плане; в остальных местах ваши клавиши ведут себя обычно.

Не знаете имя процесса? Нажмите **Выбрать прил.…** и выберите его из списка запущенных программ (показываются по заголовку окна и исполняемому файлу). Главная горячая клавиша F8 всегда работает, независимо от активного приложения.

## Язык

Выберите язык в раскрывающемся списке в правом верхнем углу окна. Выбор сохраняется в `config.json`, и приложение перезапускается для применения; «Авто» следует языку UI Windows.

Встроенные языки: English, 简体中文, 繁體中文, 日本語, 한국어, Español, Français, Deutsch, Русский, Português, Italiano, العربية, עברית.

Языки справа налево (арабский, иврит) зеркалят всю раскладку окна через `WS_EX_LAYOUTRTL` (`RightToLeftLayout` в walk).

Порядок разрешения: переменная окружения `TURBOKEY_LANG` (`zh`/`en`), затем сохранённый выбор, затем язык ОС.

Каталоги сообщений — это обычный JSON в `internal/i18n/locales/`, встроенный через `go:embed`. Чтобы добавить язык, поместите `internal/i18n/locales/<code>.json` (скопируйте `en.json` и переведите значения) и пересоберите.

## Предостережения

- Глобальный хук клавиатуры плюс инъекция ввода могут вызвать ложные срабатывания антивируса.
- Некоторые онлайн-игры запрещают макросы/автоматизацию в условиях обслуживания, а системы анти-чита могут обнаруживать или блокировать синтетический ввод. Используйте ответственно и на свой страх и риск.
